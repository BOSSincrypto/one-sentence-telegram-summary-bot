# Дайджест-бот для Telegram-каналов

Читает публичные Telegram-каналы, сжимает каждый пост за сутки в **одно предложение**
со ссылкой на оригинал и присылает готовый дайджест в нужную тему супергруппы.
Всё настраивается прямо в боте: каналы, группы каналов, получатели, модель ИИ,
фильтры, расписание.

```
📰 🗞 Новости
за 24 ч · 3 канала · 17 постов

📣 Медуза — LIVE · 5
 1 · Ураган в Ростовской области: один погибший, 13 пострадавших, задержаны 90 поездов.
 2 · ЦБ снизил ключевую ставку до 12% годовых.
 …
Также писали про: курс рубля, выборы в Молдове

📣 РИА Новости · 6
 ▸ (свёрнуто, раскрывается по тапу)
```

Цифра слева — ссылка на исходный пост. Текст остаётся чистым, поэтому лента
читается как список предложений, а не как стена подчёркнутых ссылок.

## Как это устроено

```
cron-job.org ──HTTP──► /tick ──┐
                               ├─► t.me/s/<канал>  (HTML, без API и подписок)
Telegram ────webhook──► /tg/… ─┘        │
                                        ▼
                             фильтры → дедупликация → OpenRouter → рендер
                                        │
                                        ▼
                             тема в супергруппе / личка
```

Ключевые решения приняты ради стоимости:

| Решение | Зачем |
|---|---|
| **Один запрос к ИИ на канал**, а не на пост | Системный промпт не дублируется, а бесплатные модели OpenRouter дают всего **50 запросов в сутки** — по-постно в этот лимит не уложиться в принципе |
| **Кэш саммари по хэшу текста** | Предпросмотр, повторный запуск и репост стоят ноль |
| **Дедупликация до обращения к ИИ** (SimHash) | Новость, которую перепечатали пять каналов, оплачивается один раз |
| **Локальные фильтры до ИИ** | Реклама, посты без текста и стоп-слова отсеиваются бесплатно |
| **Короткие посты — без ИИ** | Если пост и так одно предложение, модель не вызывается |
| **Машина на Fly спит** | Просыпается на вебхук и дважды в сутки на дайджест |
| **selectolax вместо BeautifulSoup** | Парсер на Lexbor: в разы быстрее и заметно экономнее по памяти |
| **SQLite на томе, без ORM** | Ноль внешних зависимостей и нулевые накладные расходы |

Всего четыре зависимости: `aiogram`, `aiohttp`, `selectolax`, `tzdata`.

### Почему каналы читаются через `t.me/s/`

Публичный веб-превью канала отдаётся сервером как обычный HTML. Не нужны ни
Bot API (боты не могут читать чужие каналы), ни user-сессия с номером телефона.
Требуется только, чтобы у канала был включён публичный доступ — иначе `t.me`
отвечает редиректом, и бот сообщает об этом понятной ошибкой.

## Запуск на Fly.io

### 1. Бот в BotFather

Создайте бота, сохраните токен. Свой числовой id узнаете, отправив боту `/id`
после первого запуска, или через `@userinfobot`.

### 2. Деплой

```bash
fly launch --no-deploy          # поправьте app в fly.toml
fly volumes create digest_data --size 1 --region ams

fly secrets set \
  BOT_TOKEN='123456:AA…' \
  OWNER_IDS='123456789'

fly deploy
```

Освободите выделенный IPv4, который `fly launch` выдаёт по умолчанию, — он стоит
$2/мес, то есть дороже самой машины. Для HTTPS на `*.fly.dev` хватает общего:

```bash
fly ips list
fly ips release <выделенный-v4>
fly ips allocate-v4 --shared
```

Вебхук бот ставит себе сам при старте: `BASE_URL` выводится из `FLY_APP_NAME`.

### 3. Будильник

Машина спит, а Fly не умеет будить её по расписанию, поэтому наружу торчит
адрес `/tick`: запрос на него поднимает машину, она проверяет, не пора ли слать
дайджест, и снова засыпает.

Откройте в боте **⚙️ Настройки → ⏰ Будильник** — там готовые адрес и расписание.
Создайте задачу на [cron-job.org](https://cron-job.org) с этими значениями.

Чтобы не держать расписание в двух местах, добавьте ключ API — тогда бот будет
создавать и переписывать задачу сам при каждой смене времени дайджеста:

```bash
fly secrets set CRONJOB_API_KEY='…'
```

### 4. Настройка в боте

`/menu` → и дальше по разделам:

1. **📡 Каналы** — добавьте каналы (`@name`, `t.me/name` или ссылка, можно списком).
2. **🗂 Группы** — создайте группу, отметьте её каналы.
3. **📍 Куда слать** — добавьте бота в супергруппу, напишите `/bind` в нужной теме.
   Бот запомнит тему и сразу удалит своё сообщение.
4. **🧠 ИИ** — вставьте ключ [OpenRouter](https://openrouter.ai/keys) и выберите
   модель. Кнопка **⚡ Быстрый старт** соберёт цепочку из актуального каталога:
   дешёвая основная + бесплатная запасная.
5. **👁 Предпросмотр** — проверьте результат в личке, ничего никуда не отправляя.

## Сколько это стоит

| Статья | В месяц |
|---|---|
| Машина `shared-cpu-1x` 256 МБ (просыпается ~2 раза в сутки) | **≈ $0.05** |
| Том 1 ГБ | **$0.15** |
| Общий IPv4 | **$0** |
| ИИ: 10 каналов × 25 постов в сутки, дешёвая модель со structured outputs | **≈ $0.15** |

Итого меньше **$0.5/мес**. На бесплатной модели — только инфраструктура,
около $0.2/мес.

Цифры зависят от выбранной модели: в разделе **📊 Статистика** видно, сколько
токенов и долларов ушло по каждой модели, а в **🧠 ИИ → 💰 Лимит** можно
поставить месячный потолок, после которого бот перестаёт обращаться к ИИ.

> У Fly.io с 2026 года нет бесплатного тарифа для новых аккаунтов — платить
> придётся в любом случае, вопрос только в сумме.

## Что умеет админка

**Каналы** — добавление списком с проверкой каждого, включение/выключение,
диагностика (когда последний раз читался, что сломалось).

**Группы каналов** — свой набор каналов, свой получатель, своя модель, свой
лимит постов, свои белый и чёрный списки слов. Предпросмотр в личку и отправка
по кнопке.

**ИИ** — живой каталог OpenRouter с поиском и фильтрами (бесплатные, дешёвые,
со structured outputs) и ценой за 1M токенов. Цепочка до 4 моделей: если первая
недоступна или упёрлась в лимит, берётся следующая. Отдельно настраиваются длина
предложения, длина обрезки поста и месячный лимит расходов.

**Настройки** — время и часовой пояс, окно сбора, лимиты постов, все фильтры,
оформление (время поста, просмотры, порог сворачивания), уведомления об ошибках.

**Статистика** — расход по моделям за 30 дней, история запусков, экспорт и импорт
конфигурации в JSON (ключ OpenRouter в файл не попадает).

## Локальная разработка

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt

export BOT_TOKEN='…' OWNER_IDS='…' DB_PATH=./bot.db
python -m app.main          # без BASE_URL включается long polling
```

```bash
pytest -q                   # 103 теста, сеть не нужна
ruff check app tests && ruff format --check app tests
```

Сеть в тестах не используется. Парсер проверяется на фикстуре, воспроизводящей
реальную разметку `t.me/s/` (блок ответа, пост без текста, служебное сообщение,
постраничный курсор); доступ владельца — прогоном настоящих `Update` через
настоящий `Dispatcher`; `/tick` — через поднятый aiohttp-сервер.

## Что стоит знать

* **Ключевые слова ищутся подстрокой, без учёта морфологии.** «крипта» не поймает
  «крипту» — вводите основу: «крипт».
* **Дедупликация ловит перепечатки, а не пересказы.** SimHash сравнивает тексты;
  одна и та же новость, написанная разными словами, останется двумя строками.
* **Отбор по охвату идёт до проверки на рекламу.** Если модель пометит уже
  отобранный пост рекламой, он выпадет, и в дайджесте окажется меньше строк, чем
  стоит в лимите. Добирать посты повторным запросом было бы дороже, чем оно того
  стоит.
* **Темы форума собираются из того, что Telegram присылает боту.** При включённом
  privacy mode (по умолчанию) это создание новых тем и `/bind`. Если выключить
  privacy mode в BotFather, бот увидит все сообщения группы и соберёт темы сам —
  но каждое сообщение будет будить спящую машину.
* **Пропущенный дайджест не досылается задним числом**: окно всегда «последние
  24 часа», так что следующий запуск и так покроет пропуск.
* **Образ Docker в этой среде не собирался** — сборка и smoke-тест выполняются
  в CI при первом пуше.
